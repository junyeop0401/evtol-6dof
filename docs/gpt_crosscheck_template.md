# GPT 교차검증 핸드오프 템플릿

GPT(ChatGPT)는 이 프로젝트에 API/MCP로 연결되어 있지 않다. 그래서 Claude가 아래
형식으로 "검토 요청" 블록을 만들면, 사용자가 그대로 복사해 ChatGPT에 붙여넣고
회신을 다시 가져와 Claude에게 전달하는 수동 핸드오프 방식으로 쓴다. 목적은
같은 모델(Claude)이 작성하고 같은 모델이 다시 검토하면서 생기는 맹점을, 완전히
다른 모델 계열로 한 번 더 걸러내는 것이다.

## 언제 쓰는가

- 논문에 실제로 실릴 최종 결과(개념설계 확정, 최종 손계산, 최종 CSV 판정)
- 확신이 낮거나 반대 근거가 있을 수 있는 설계 판단(예: PID 게인 도출, 좌표계
  부호 해석, 공력계수 추정 근거)
- QuadX_Baseline 같은 파이프라인 검증용 중간 산출물에는 기본적으로 쓰지 않는다
  (매번 쓰면 오버헤드만 커짐 — Claude가 "고위험"으로 판단한 항목에만 사용)

## 요청 블록 형식

```
## GPT 교차검증 요청 — <날짜> — <대상>

### 배경
<이 산출물이 왜 필요한지, 지금까지 어떤 경로로 여기까지 왔는지 2~3문장>

### 검토 대상
- 파일: <경로>
- (필요시 파일 원문 전체 또는 핵심 발췌를 이 아래에 붙여넣음)

### Claude의 판단과 근거
<Claude가 이미 내린 결론과 그 근거를 요약. GPT가 "빈 백지"에서 다시 풀지 않고
Claude의 논리 사슬 자체를 검증하도록 명시적으로 제공>

### 구체적 질문
1. <예: 이 손계산의 전제/공식이 맞는가, 반례가 있는가>
2. <예: 이 좌표계 부호 해석이 JSBSim 공식 문서와 정합하는가>
3. <예: 이 CSV 판정 기준(오버슈트/정착시간 임계값)이 이 미션 목적에 합리적인가>

### 기대 회신 형식
- 동의/부분동의/반대 중 하나로 명시
- 반대하거나 부분동의라면 구체적 근거와 수정안을 제시
- 확인이 불가능한 부분(예: 실제 실행 없이는 알 수 없는 것)은 그렇게 명시
```

## 회신 처리 방식

1. GPT 회신을 그대로 Claude에게 전달한다(요약하지 말고 원문 그대로).
2. Claude가 회신을 검토해 반영/기각을 판단하고, 근거를 `docs/STATUS.md` 로그에
   남긴다(반대 의견을 기각할 때도 왜 기각했는지 반드시 기록 — 이 프로젝트의
   "엄격한 자체 검증" 원칙과 동일하게, GPT 의견도 맹신하지 않고 근거로 판단한다).
3. 산출물 수정이 필요하면 파이프라인의 해당 단계(XML 작성 또는 정량분석/판정)로
   되돌아간다.
