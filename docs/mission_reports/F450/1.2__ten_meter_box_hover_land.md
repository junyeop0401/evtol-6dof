### 좌표계 확인

- Lat에 `type="geodetic"` 명시(측지위도), Lon은 type 구분 없음(경도는
  geodetic/geocentric 차이 없음) — `2.0`이 쓰는 `1.0__ground_park_init.xml`과
  동일 지점(위경도), 헤딩(ψ₀)만 90°→0°로 바뀜.
- φ₀/θ₀/ψ₀는 오일러각(도), 동체좌표계(X=기수전방+, Z=하방+) 기준. ψ₀=0°는
  진북을 향해 정지.
- **h₀ vs h_terr — `2.0`이 쓰는 초기조건과 달리 정상.** h₀=0.0 m,
  h_terr=285.2111 m. JSBSim 1.2.4의 `initialize/altitude`(h₀)는 AGL로
  해석되므로(`reference/docs/lessons_learned.md` 1절) h₀=0.0은 지면 높이(0
  AGL)를 정확히 의미하고, 실제 콘솔 로그 첫 notify(t_sim=0.002s)에서도
  h_AGL=-0.000000으로 즉시 확인된다 — `2.0`이 쓰는
  `1.0__ground_park_init.xml`(h₀=285.2111 m, h_terr와 동일값)이 h_AGL=935.7 ft
  (285 m 상공)에서 스폰되는 결함이 있는 것과 대조적
  (`docs/mission_reports/F450/2.0__nominal_mission_profile.md` 초기조건 절
  참고). 이 초기조건 파일이 두 시나리오 중 올바른 참조 형태.

## 2. Runscript 이벤트별 조건/명령

로컬 좌표계는 north=x, east=y, altitude AGL=z. 목표 고도는 시종일관
h_sp=32.80839895 ft(=10.0002 m), 이동/호버 이벤트에서는 위치·고도·속도 오차가
모두 수렴해야 다음 상태로 전환되는 "오차수렴+시간" 이중 게이트 방식이다.

정의: **Conv ≡ (−2≤e_N≤2 m) ∧ (−2≤e_E≤2 m) ∧ (−3≤e_h≤3 ft) ∧ (−3≤v_N≤3 fps)
∧ (−3≤v_E≤3 fps) ∧ (−2≤ḣ≤2 fps)** — 6개 범위조건(개별 부등식 12개)을 모두
AND로 만족해야 참. 표에서는 이 이름만 쓴다.

next-event-time(재알림 타이머 갱신용 Δ-set, `../_notation_common.md` 참고)은
미션 로직에 영향을 주지 않는 부기용 프로퍼티라 아래 표의 명령 목록에서
생략했다.

조건으로 요구한다는 점이다.

## 3. 분석 — 정상 작동했는가

**의도대로 정상 작동했다.**

| 항목 | 값 | 비고 |
|---|---|---|
| 이륙 시각 | t ≈ 2.1s | 3개 랜딩기어 동시 지면 이탈 |
| 목표 고도 | 32.808 ft (10.0002 m) | |
| 고도 오버슈트 | 없음 | t=25s: 32.70 ft → t=41s: 32.806 ft, 단조 수렴 |
| 첫 웨이포인트(북 10m) 도달 | t = 40s(설계상 최초 허용 시각) | 위치오차 약 0.5 m (허용 ±2 m) |
| 전체 8구간 박스 패턴 완주 | t ≈ 204s | s_mis=18 도달 확인 |
| 착륙 시각 | t = 205.12s | 3개 랜딩기어 동시 접지(수평 착지) |
| 최종 위치 오차(출발점 대비) | 약 1.8 mm | distance-from-start-lat/lon-mt ≈ (0.0013, 0.0013) |
| 최대 자세 편차(횡이동 가속 구간) | 약 -2.7 deg pitch (t≈26s) | 안전 범위 내 |
| 시동정지/종료 | t=205s(disarm) → t=210s(terminate) | 설계된 이벤트 조건대로 정확히 진행 |

이 미션은 m_ap를 통해 F450AP.xml 자동조종을 정식으로 engage하는 방식이라,
자동조종이 매 프레임 계산하는 δ_thr 등과 충돌하지 않는다
(같은 기체의 `2.0__nominal_mission_profile`이 이 방식을 안 써서 아예 이륙조차
못 했던 것과 대조적 —
`docs/mission_reports/F450/2.0__nominal_mission_profile.md` 참고). 고도/위치
홀드 모두 오버슈트 없이 단조 수렴하는 깨끗한 응답을 보였고, 이는
QuadX_Baseline의 open-loop 스로틀 스테이징이 243 ft 오버슈트로 실패했던
사례와 정반대의 결과다.

## 4. 결론

이 시나리오는 F450 기체와 F450AP 자동조종 조합이 m_ap 기반 폐루프
제어에서 정확하고 안정적으로 작동함을 검증한다 — 이륙, 8구간 박스 이동, 정밀
호버, 수직 착륙, 시동정지까지 전 과정이 오버슈트 없이 설계대로 완료됐다.
다음에 반영할 점: 틸트로터 본체 설계에서도 위치/고도 제어는 이런 폐루프 +
오차수렴 게이트 패턴을 기본값으로 채택해야 한다.
